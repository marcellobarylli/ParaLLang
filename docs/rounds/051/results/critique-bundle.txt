===== docs/rounds/051/trail/plan-v1.md
     1	# Round 051 plan v1: an early pass in an ordered encounter is not a success (backlog H1)
     2	
     3	Autonomous round (no owner present).
     4	
     5	## Problem (round 050 data)
     6	
     7	In an ordered encounter (every encounter except `mortimer_tasting`), `submitDialogue` grades every remaining
     8	objective and closes only the leading run of passes (`learning-service.js`, "In order: the leading run of passes
     9	closes"). When a later objective passes while an earlier one fails, three things tell the player it succeeded,
    10	though it stays open and must be met again:
    11	
    12	1. the grader's `feedback` for it: "You successfully insist on now. You still need to tell Flick what time it is."
    13	   (round 050, run 1 it and es);
    14	2. the app's Assessment panel shows ✓ for it (`DialoguePanel.js`: `result.passed ? '✓' : '→'`);
    15	3. the narrator gets `authoritative_decision.objectiveResults` with `passed: true` and reacts as to a success
    16	   ("¡Ahora, sí! No quieres esperar.").
    17	
    18	Two turns later the player is asked to say "now" again.
    19	
    20	## Design
    21	
    22	1. **`held` on a result** (server). In an ordered encounter, a result that passed but does not close (it follows a
    23	   failed objective) is marked `held: true`, in both `decision.objectiveResults` (narration) and the response's
    24	   `assessment.objectiveResults`. The field is added only when true, so every other prompt and response stays
    25	   byte-identical (Gerald's pinned narration prompts, `server/test/fixtures/gerald-prompts-r026.json`). Unordered
    26	   encounters never hold. `passed` keeps the grader's verdict (the evidence was correct usage; the Spellbook
    27	   records it as now).
    28	2. **Grading prompt** (`prompts/language/grading.txt`, filled from `buildGradingMessages`): a conditional ORDER line
    29	   after the rubric, only when the encounter is ordered and more than one objective is supplied (empty otherwise,
    30	   like `ambientLine`): "ORDER: the objectives count in the order given. If an objective passes while an earlier
    31	   one has not, its feedback must say in English that it will count once the earlier one is done, not that it
    32	   succeeded." `buildGradingMessages` gets `ordered` (boolean).
    33	3. **Narration** (`prompts/encounter/dialogue_turn.txt` unchanged): `held: true` is self-describing inside the
    34	   authoritative decision, plus one sentence added to the TURN DATA only when a held result exists:
    35	   `held_note: "A held objective was said correctly but does not count yet: an earlier objective comes first."`
    36	   (inside `authoritative_decision`, only when held, so pinned prompts stay identical).
    37	4. **App** (`mobile/src/components/DialoguePanel.js`): a held result shows `…` instead of ✓, and its line ends with
    38	   "(counts once the earlier objective is done)". The frozen web client is unchanged (it shows ✓; noted).
    39	5. **Tests:** service test (Fountain fixture: "Adesso!" at `time` gives `now` held in the response and in the
    40	   narration call's decision; a combined answer gives no held); unordered (`mortimer_tasting`) never holds; grading
    41	   prompt has the ORDER line for an ordered multi-objective call and not for single or unordered; Gerald's pinned
    42	   prompts unchanged; mobile component test for `…` and the note.
    43	
    44	## Live
    45	
    46	codex-cli, `play-market.js --location cracked_fountain` (the script holds "Adesso!" at `time`), 1 × it, 1 × es.
    47	Measure: feedback for the held `now` (says it will count later, not success), Flick's next line (does not treat
    48	now as achieved), all verdicts as scripted. Then `npm run verify:cli -- --provider codex-cli` as Gerald's regression.
    49	
    50	## Success
    51	
    52	All tests pass; in both live runs the held objective's feedback does not call it a success and the verdicts match
    53	the script; verify:cli passes.

     2

    21	function targetData(objectives, vocabularyById, { forms = false } = {}) {
    22	  return objectives.map((objective) => ({
    23	    id: objective.id,
    24	    intent: objective.intent,

    30	    required_target_groups: objective.required_target_groups,
    31	    grammar_constraints: objective.grammar_constraints,

    37	// Round 019: an encounter's ambient vocabulary, as one extra line after the learning data; empty when it has none, so
    38	// prompts without it stay byte-identical (Gerald's golden prompts).
    39	function ambientLine(language, entries) {
    40	  if (!entries.length) return '';
    41	  const words = entries.map((entry) => ({
    42	    target: entry.target, meanings: entry.accepted_translations, ...(entry.note ? { usage: entry.note } : {}),
    43	  }));
    44	  return `\nFREE VOCABULARY (authored ${language.name} you may use in any line, including the greeting; it is not the answer to any objective, and every rule above about open objectives still applies): ${JSON.stringify(words)}`;
    45	}
