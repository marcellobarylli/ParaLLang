# Round 002 implementation packet: Playtest ParaLLang through Codex and Claude Code subscriptions

## Scope

Deliver the whole feature in one implementation run with one final owner review. Both CLI providers, configuration, failure handling, focused tests, documentation, and available live verification belong to this round. Internal dependencies do not create intermediate owner gates.

1. Add **codex-cli** and **claude-cli** to the existing provider registry, implementing CodexCLIAdapter and ClaudeCLIAdapter behind the current interface. Route both Gerald's narration and dialogue grading through the selected CLI. Keep OpenAI API and Ollama available and preserve server-owned learning decisions.
2. Use each official CLI's native subscription sign-in. Require ChatGPT authentication for Codex and native claude.ai subscription authentication for Claude Code. Use a controlled child environment and invocation-level configuration so API keys, alternate authentication, custom providers, or inherited settings cannot silently select a different billing/account path. Do not read/copy token files, extract OAuth credentials, edit global CLI configuration, or fall back to another provider, model, or API billing.
3. Support LLM_PROVIDER=codex-cli or claude-cli, optional LLM_MODEL, optional CODEX_CLI_PATH/CLAUDE_CLI_PATH executable paths, and LLM_CLI_TIMEOUT_MS with a 120000 ms default and validated 1000–300000 ms range. When no model is specified, delegate to the selected CLI's default rather than an API model default. Load the root .env consistently and preserve existing local configuration.
4. Add **npm run check:provider** with an optional --provider override. Check executable/version/capabilities, effective isolation, and subscription-authentication category under the same environment as generation, without an inference request. Use the same preflight before serving the first CLI-backed game request. Provide safe, actionable setup failures while keeping existing learning data accessible.
5. Implement a shared bounded subprocess runner using direct executable spawning and stdin for game input. Preserve instruction/data roles and message order; use fresh isolated invocations with the service's explicit history. Parse native successful structured results, validate with existing Zod schemas, and retain existing semantic grading checks. Do not parse free-form model prose into game outcomes.
6. Disable coding tools, web/external tools, MCP/apps, hooks, unrelated instructions/customizations, memory, and session reuse through supported native controls while preserving native authentication. Use private temporary working/schema/prompt files outside the repository and a restrictive sandbox. Verify the installed versions' effective controls; reject unsupported configurations before generation. Do not install/upgrade CLIs or bypass managed restrictions automatically.
7. Bound generation to one active process and eight queued calls per server, with queue waiting counted against the call deadline, 1 MiB stdout and 64 KiB stderr limits, bounded termination/reaping, temporary-file cleanup, and server-shutdown cleanup. Add no application-level automatic generation retries. Bind CLI-mode service access to loopback and keep the existing Vite proxy working.
8. Propagate allowlisted provider failures for setup/authentication/model/quota/busy/timeout/output/response/process errors. Keep browser and ordinary logs free of raw stderr, prompts, account details, and credentials, including nested error causes. Preserve visible pending state and retained input. A grading success followed by narration failure must leave the whole turn uncommitted; preserve assistance records, stale-tab behavior, learner isolation, and receipt replay.
9. Update README, .env.example, and necessary package scripts with local login, provider/model selection, startup, verification, tested CLI versions, and troubleshooting. No embedded login or provider-selection UI is required. Add only directly necessary dependencies or client changes.
10. Add and run exactly the focused deterministic checks and selected existing tests/build specified in the architecture. Add **npm run verify:cli -- --provider codex-cli** and its claude-cli equivalent as explicit live verification entry points. Exercise authored grading cases and a complete live encounter for each available subscription, plus the real browser path when tooling permits, using temporary saves and at most 20 generation calls per provider in total. Report actual models, versions, isolation controls, results, timing, call counts, and unavailable checks.
11. Preserve earlier scope boundaries: browser pronunciation, canonical content, hint/assistance rules, local reviews, scheduling, and durable Spellbook semantics remain intact. The known Spellbook meaning leak is recorded but its policy is not changed in this round. Open-model evaluation remains later work through Ollama.
12. Preserve orchestration configuration. The existing setup = "npm ci" already recreates workspace dependencies; no configuration addition is authorized or needed, and no broad check runs automatically.

Complete the integrated scope before presenting the final owner review. Account or environment limitations must be reported honestly without converting them into separately accepted implementation stages.

## Acceptance

The architecture's Test plan defines the checks; the observable outcomes are:

1. **Codex subscription play:** with a compatible installed CLI and valid subscription access, selecting codex-cli obtains Gerald's greeting and completes a browser-playable encounter with validated grading and narration.
2. **Claude subscription play:** selecting claude-cli provides the same complete flow independently through Claude Code's native subscription login.
3. **Correct authentication:** the setup check reports the selected provider, CLI version, native subscription-auth category, and requested model/default without inference or private details. Conflicting API credentials or unsupported configuration cannot silently change the authentication/billing path.
4. **Predictable model selection:** an explicit LLM_MODEL reaches the selected CLI; omission uses its configured/default model. Unavailable models yield actionable errors. Existing OpenAI and Ollama defaults still work in their contract tests.
5. **Structured authoritative results:** both providers return schema-valid game objects from successful CLI completions. Invalid JSON/schema, ambiguous/missing final payloads, provider failure envelopes, and unsuccessful exits cannot advance an encounter. Server grading remains authoritative over narrator flags.
6. **Isolated requests:** game context is supplied explicitly; another learner, coding session, project instruction, hook, or configured integration cannot contaminate the request. Required tool/integration restrictions are checked on the supported CLI configuration, not merely requested in a prompt.
7. **Bounded execution:** missing binaries, incompatible versions/configuration, login failure, quota exhaustion, unavailable models, queue saturation, timeouts, output overflow, interruptions, and shutdown terminate cleanly with safe feedback. Children and temporary runtime files are cleaned up.
8. **No partial learning commits:** provider failure preserves input and leaves encounter/Spellbook progress unchanged, including when grading succeeded before narration failed. A successful retry commits once. Redelivery of an already committed attempt performs no new generation and does not score again. Previously requested help remains recorded.
9. **Usable local development:** documented configuration plus npm run dev serves the existing browser app through a working loopback backend/proxy. Pending and failure states are understandable. No credentials, raw process output, or private account metadata appear in the browser or ordinary logs.
10. **Focused regression evidence:** all selected new/existing deterministic tests and the client build pass. Existing provider contracts, prompt assembly, relevant learning/storage receipts, and selected client behavior remain covered. No unrelated suite is required.
11. **Live evidence per provider:** the report distinguishes fixture behavior from live grading for the positive, mixed-language, English-only, contextual, negated, quoted, off-topic, and third-person cases. It records a real complete encounter, selected/resolved model when available, CLI version, response times, and generation count for each verified provider.
12. **Honest limitations:** a missing/expired login, unavailable model, exhausted quota, incompatible isolation controls, or absent browser tooling is stated specifically. Mock success or native auth status does not count as live readiness. A provider blocked from live verification remains an explicit acceptance gap, not an implied pass.
13. **Whole-round delivery:** both adapters and their setup/error/test/documentation paths are integrated before the one final owner review. No placeholder provider, hidden API fallback, one-provider-only handoff presented as complete, or intermediate acceptance checkpoint satisfies this packet.

- A provider picker, account-management UI, streaming, a token/cost dashboard, broad visual redesign, mobile applications, or a general agent orchestration framework.
- New encounters/maps/world progression, full game save/load, persisted conversations, cloud sync, database migration, new teaching content, grading-policy redesign, scheduling changes, and unrelated refactors.
- Fixing or accepting the prior Spellbook answer-visibility leak. Its owner policy decision remains separate.
- Speech recognition, narrated/provider TTS, ambient audio, physical speaker checks, and device-specific voice-quality assessment.
- Automatic broad checks, unselected tests/simulations, dependency audits/remediation, release validation, load tests, and repeated live runs to hide stochastic failures.
- Owner-only operations: interactive account login/recovery, purchasing access, granting entitlement or increasing quota, changes to private-network access, unavailable browser/device testing, and listening to physical audio. Use already available access; report missing checks without inventing a new owner gate.
